## 二、文本题从创建到统计

步骤：

1. A在“个人题库”页面创建选答文本题，形成版本1。
2. 点击版本1的“以此版创建新版”，原样保存得到内容完全相同的版本2；再基于版本1修改题干，保存得到版本3。保存text-three-versions.png。
3. A将逻辑题目分享给B。A创建并发布使用版本1、版本3的两份问卷；B创建并发布使用版本2的问卷。选题和发布均通过页面操作。
4. R1—R5分别登录，依次填写三份问卷：版本1、版本2填写“重复答案”，版本3填写“其他版本答案”，共15份。
5. R6只填写版本2问卷，输入“只出现一次的私人内容”，共计16份。每次提交均等待“提交成功”并保存截图及答卷ID。
6. A打开题目详情并点击“刷新总览”，核对分组与频次；再点击版本2的“查看/统计此版”，刷新并核对单版统计。

预期与实际：

| 查询范围 | 预期 | 实际 |
| --- | --- | --- |
| 同内容版本1、2 | 合并展示，共11份答卷，“重复答案”10份 | 符合 |
| 不同内容版本3 | 单独展示，5份答卷，“其他版本答案”5份 | 符合 |
| 单独查询版本2 | 6份答卷，“重复答案”5份 | 符合 |
| 一次性文本 | 页面及统计响应中不展示 | 符合 |

结果：文本题创建、版本保存、跨用户选题、发布、16次填写提交及统计展示的完整页面流程通过。页面中的答卷记录通过正常提交接口保存，补齐了此前只有合成数据页面检查的证据。

证据：[总览截图](text-overview-statistics.png)、[版本2单版截图](text-v2-statistics.png)、[完整页面](text-final-full-page.png)；目录中还保存三份已发布问卷、填写页面及16次提交成功截图。[result.json](result.json)记录每次提交的账号、版本、答卷ID和统计响应。
