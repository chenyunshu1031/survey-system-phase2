## M16 409 刷新提示

- 步骤：真实提交期间冲突由后端自动测试覆盖。若需单独验收浏览器提示，可仅在隔离页面打开开发者工具 Console，临时把跨问卷统计 GET 响应替换为 409，然后点击题目详情“刷新统计”；完成后刷新页面恢复原 `fetch`。不得在真实业务页面执行。
- 输入：模拟 HTTP 409、`{"detail":"统计期间有提交或范围变化"}`。可用下面临时代码；它不发送密码或令牌，也不修改服务端：

```js
const originalFetch = window.fetch.bind(window);
window.fetch = (input, init) => String(input).includes('/cross-survey-statistics') && (!init?.method || init.method === 'GET')
  ? Promise.resolve(new Response(JSON.stringify({detail: '统计期间有提交或范围变化'}), {status: 409, headers: {'Content-Type': 'application/json'}}))
  : originalFetch(input, init);
```

- 预期：页面显示“统计期间有提交或范围变化，请刷新统计后重试”一类提示，不把旧结果当成新结果。之后刷新浏览器页面即可恢复 `window.fetch`。
- 实际：**通过（助手浏览器 UI 模拟）**。因应用内浏览器没有可用的 Console 注入入口，临时建立本地测试 HTML，仅将同页第 2 次统计 GET 模拟为 409，其他请求转发给原 API。第一次刷新显示正常的 5 份答卷和均值 4；第二次刷新显示“统计期间有提交或范围变化，请刷新统计后重试”，旧计数与均值从页面消失；第三次刷新恢复正常结果。测试 HTML 已删除，页面已回到正常入口。真实并发 API 409 另由后端测试覆盖，本项只证明 UI 处理。
