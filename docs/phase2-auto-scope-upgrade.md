# 第二阶段自动汇总版本的本机更新记录

本轮将题库改名与归档、旧问卷题目显式保存、自动纳入有效同版问卷的聚合统计接入现有本机服务。原业务库仍为`127.0.0.1:27017/survey_system`，数据目录仍为`backend/.local-mongo-data`。业务功能先在隔离MongoDB和浏览器测试；本轮正式库操作没有插入测试答卷。

## 操作顺序

1. 用MongoDB的`getCmdLineOpts`核实27017连接的确实是项目数据目录。更新前保存四个旧集合的数量、原ID和完整文档哈希。
2. 核对8000端口进程属于本项目后停止API。当前MongoDB 8.3.11不接受`mongod --shutdown`选项，因此改用经数据目录核实的`admin shutdown`正常关库；确认27017端口关闭后才复制数据目录。
3. 将停库后的数据目录复制到独立备份目录，67个文件逐一比对SHA-256。备份目录为`../output/phase2-auto-scope-upgrade-20261027_195755/mongo-before/`。
4. 执行`start-local.ps1`，从原项目数据目录启动MongoDB及当前FastAPI代码，复用已有前端服务。脚本返回页面与数据库就绪。
5. 只读核对旧集合与新增结构；请求8000端口OpenAPI及5173首页。

## 实际核对

| 项目 | 结果 |
| --- | --- |
| 离线备份 | 67个数据文件的大小和SHA-256与原目录一致 |
| 原集合记录数 | `users`7、`surveys`8、`questions`24、`responses`11，更新前后相同 |
| 原集合内容 | 四集合的原ID列表及完整文档SHA-256逐项相同 |
| 数据库结构 | 10个集合的校验器与当前`schema.py`定义一致；旧题保存唯一索引、来源查询索引存在 |
| 服务 | 当前OpenAPI包含题库改名、旧题保存、逻辑题目总览及单版自动统计路径；前端首页HTTP 200 |
| 隔离功能回归 | 后端106项通过、0失败、0跳过；前端12项通过、类型检查与生产构建通过；B02浏览器验收留有截图 |

具体机器记录位于`../output/phase2-auto-scope-upgrade-20261027_195755/`：`before-state.json`、`backup-verification.json`、`after-state.json`。B02隔离页面截图见`../output/phase2-gap-browser-20261027072710/`。阶段二详细用例见[测试用例与结果](phase2-test-cases.md)。

本轮只在原库上验证结构、旧记录与路由加载，未用合成账号向原库执行新业务写入。自动统计的“所有问卷”仍限定为带有效来源快照的问卷；旧题不凭相同题干自动归并，显式保存旧题不追溯合并历史答卷。
