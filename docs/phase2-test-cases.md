# 基于MongoDB的在线问卷系统——第二阶段测试用例与结果

## 一、范围、环境与执行方法

测试覆盖第一阶段的问卷创建、四种题型、条件跳转、输入校验、答卷提交和单问卷统计，以及第二阶段的题目复用、版本历史、分享、题库管理和跨问卷统计。第一阶段回归用例为T01—T22，第二阶段用例为P2-01—P2-21。测试采用自动接口测试、真实MongoDB集成测试和浏览器操作相结合的方式。

| 环境 | 用途 | 数据边界 |
| --- | --- | --- |
| FastAPI TestClient＋mongomock | 接口、权限、错误分支与业务计算 | 每项测试准备独立数据 |
| MongoDB 8.3.11隔离实例 | 验证真实校验器、唯一索引及重复初始化 | 127.0.0.1:29141，随机测试库 |
| Edge页面＋Playwright | 验证真实前端操作、提示和结果展示 | 127.0.0.1:15173、18000及隔离库unit6_browser |
| 第一阶段备份副本与原库切换记录 | 核对旧记录和旧接口 | 旧数据的读取、ID、引用及内容哈希 |

下文省略统一的`/api/v1`前缀。接口测试使用登录令牌`Authorization: Bearer <token>`，对象ID取自对应的创建响应；创建题库、题目、版本及保存旧题时携带`Idempotency-Key`。A为题目作者，B为获分享者，R1—R6为填写测试账号。浏览器测试包含本人手工操作和AI辅助执行，执行方式随具体用例记录。

后端回归在隔离MongoDB启动后执行。在`backend`目录配置以下环境变量并运行测试：

```powershell
$env:RUN_MONGO_INTEGRATION = '1'
$env:MONGO_TEST_URI = 'mongodb://127.0.0.1:29141'
$env:RUN_LIBRARY_MONGO_INTEGRATION = '1'
$env:LIBRARY_MONGO_TEST_URI = 'mongodb://127.0.0.1:29141'
$env:FRONTEND_ORIGIN = 'http://localhost:5173'
python -m pytest -q
```

前端在`frontend`目录执行`npm test`和`npm run build`。新增业务的创建与填写测试使用隔离库；旧数据兼容检查使用备份副本和原库更新记录。

## 二、实验要求的六类核心测试

### P2-01 创建问卷和账号隔离

目的与前提：确认阶段二仍从原账号系统创建问卷，问卷所有权没有因新增题目分享而改变。准备两个不同的测试账号A和B。

测试步骤：

1. A登录，在“我的问卷”输入标题“U6-A同版问卷”并创建。
2. 检查创建后的状态和草稿编辑页，再返回问卷列表读取该问卷。
3. B登录，查看自己的问卷列表，并尝试读取或编辑A的问卷。接口越权响应按第一阶段T01复核。

输入：两个独立账号；问卷标题“U6-A同版问卷”；B使用A问卷的实际ID。

预期输出：A得到草稿且可管理；B的列表不出现A问卷，不能按ID管理它。

实际输出：浏览器M01中A创建成功并进入本人草稿；账号隔离的接口断言由T01及后端回归覆盖，越权读取与添加返回404。结果：通过。证据：验收记录M01、第一阶段T01、test_first_slice.py。

### P2-02 添加题目和从题库选题

目的与前提：确认第一阶段的四种题型和直接添加接口仍可用，并验证新选题入口生成独立实例。A拥有单选逻辑题目版本1，已分享给B；B有本人草稿。

测试步骤：

1. 按第一阶段T02，在草稿中分别添加单选、多选、文本和数字题，重新读取并核对顺序与配置。
2. A创建单选可复用题目“U6设备类型”，选项“笔记本”“台式机”，设为必答并分享给B。
3. B在草稿中两次选择该题版本1；另用原“添加题目”入口加入选答文本题“U6中间题”和必答文本题“U6终点题”。
4. 刷新列表，核对两次选入的实例ID、选项内容、来源版本与题目顺序。
5. 在草稿题卡点击“删除此题”，先取消，再确认删除；刷新后确认该实例消失，题库原题、版本及其他实例仍保留。
6. 分别尝试由其他账号删除、删除已发布问卷题目，以及删除被其他跳转规则引用的题目，核对拒绝响应。

输入：第一阶段T02的四题配置；“U6设备类型”版本1重复选入两次；两个普通文本题。

两次选题均发送以下请求，ID替换为创建逻辑题目后实际返回值：

```json
{
  "libraryQuestionId": "逻辑题目实际ID",
  "versionId": "版本1实际ID"
}
```

路径为`POST /surveys/{B问卷ID}/questions/from-library`。直接添加题目的四种配置与状态码见第一阶段T02。

预期输出：原四种题型按配置保存；两次选入有不同的问卷题目ID，但保留相同版本来源与内容快照。取消删除不改变列表，确认删除只移除当前草稿实例；越权删除返回404，发布后删除及删除跳转目标题返回409。

实际输出：T02的四题保存与顺序断言通过；M06显示两条来源题和新加文本题，隔离库核对两个实例ID不同。删除接口的权限、发布状态和跳转引用检查通过；浏览器中取消后题目仍在，确认删除并刷新后列表为空。结果：通过。证据：第一阶段T02、验收记录M02/M05/M06、test_sharing.py、[删除接口测试](../backend/tests/test_question_delete.py)及[删除页面结果](evidence/phase2/question-delete-browser-1793110567258/result.json)。

### P2-03 条件跳转与来源关系

目的与前提：确认共享版本只提供题目内容，跳转规则仍由使用它的问卷配置。B草稿中有来源单选题、位于其后的中间题和终点题。

测试步骤：

1. 在第二道来源单选题上设置“选笔记本时跳至U6终点题”，保存并刷新。
2. 检查跳转目标仍是本问卷的题目ID，来源版本标记仍在。
3. 发布后用填写者账号选择“笔记本”，观察实际页面顺序并提交。
4. 查看中间题的到达数和回答数；非法跳转目标、无效选项和优先级由第一阶段T03检查。

输入：单选equals“笔记本”；目标“U6终点题”；中间题“U6中间题”。

预期输出：修改本卷跳转规则不脱离来源版本；中间题被跳过，到达/回答均为0；后端按规则复算路径。非法规则不能覆盖有效规则。

实际输出：M09刷新后规则与来源均保留；M10答题从来源题跳至终点；M11中间题到达/回答为0；T03的非法规则断言通过。结果：通过。证据：验收记录M09—M11、第一阶段T03。

### P2-04 配置校验和填写校验

目的与前提：确认从题库选入的题目同样受第一阶段题型、选项和答案校验约束，错误输入不产生半份答卷。

测试步骤：

1. 按T04向草稿题目接口提交重复选项、不相容的题型/限制、无效数字区间，再重新读取原配置。
2. 对已经发布的必答题，在填写页先留空并尝试继续或提交。
3. 按合法访问路径填入单选“笔记本”和终点文本“ok”，再次提交。
4. 用T04的非法答案样本检查类型、选项、数字范围和文本长度的服务端响应，并核对失败后答卷数量。

输入：T04中的非法配置与答案；浏览器先留空必答题，再输入合法选项和文本“ok”。

| 输入变化 | 预期 | 实际 |
| --- | --- | --- |
| 选择题重复选项或题型与校验参数不符 | 422，原配置不变 | 第一阶段T04断言为422 |
| 到达的必答题留空 | 不允许提交 | M10页面显示“此题必答” |
| 按合法路径选“笔记本”、终点填“ok” | 保存一份答卷 | M10提交成功 |

预期输出：配置及答案错误被拒绝，原有效配置和答卷数量不变；必答题得到清楚提示；合法答案成功保存。

实际输出：T04中的非法项返回422，合法对照通过；M10留空首道必答题时显示“此题必答”，有效路径提交成功。结果：通过。证据：第一阶段T04、验收记录M10、test_responses.py。

### P2-05 提交问卷、访问路径与重复限制

目的与前提：确认阶段二仍使用原responses结构保存答案，并继续限制重复提交。问卷已发布并设置“同账号不可重复填写”。

测试步骤：

1. 填写者打开公开问卷，按规则回答来源单选题和终点题，跳过中间题。
2. 提交后查看成功提示，并以问卷所有者读取整卷统计，核对答卷数为1。
3. 使用同一填写者再次提交；按第一阶段T05检查服务端拒绝重复、漏答到达题、插入被跳过题或错误访问顺序。

输入：选项“笔记本”；终点文本“ok”；同一账号的第二次提交和T05的错误路径样本。

| 请求 | 预期 | 实际 |
| --- | --- | --- |
| 首次按Q1→终点题的有效路径提交 | 201 | M10成功；M11单卷答卷数为1 |
| 插入被跳过的中间题或遗漏到达题 | 422 | 第一阶段T05为422 |
| 同一账号重复提交 | 409 | 第一阶段T05为409 |

预期输出：第一次仅保存一份有效答卷，visitedQuestionIds包含实际到达题；错误路径和重复提交不增加答卷。

实际输出：M10浏览器首次提交成功，M11整卷答卷数为1；重复及路径错误在T05和原库真实HTTP测试中按预期拒绝。结果：通过。证据：验收记录M10/M11、第一阶段T05、切换记录。

### P2-06 统计：原单问卷与新增跨问卷

目的及前提：分别验证第一阶段单问卷统计和当前第二阶段**自动纳入所有同版问卷**的口径。A、B各有一份含同一版本有效来源快照的问卷；B未授予统计权限。

1. B查看本卷整卷统计及来源题、被跳过题的单题统计。
2. A、B两卷各由五名不同填写者提交一份答卷，均选“笔记本”；A卷有两个同版实例。
3. 保持B问卷没有统计授权；A请求`GET /library/questions/{qid}/versions/{vid}/all-survey-statistics`并刷新页面统计。
4. 再请求旧路径`GET /library/questions/{qid}/versions/{vid}/cross-survey-statistics`，检查旧授权口径仍可读取，避免把两条接口结果混淆。

输入：两卷各5份答卷；同版重复实例；B无统计授权。选项实际提交值使用该版本选项ID。

| 统计入口 | 预期参与问卷／答卷／到达／回答 | 实际 |
| --- | --- | --- |
| 当前自动同版接口 | 2／10／10／10 | 2／10／10／10 |
| 旧授权同版接口 | 1／5／5／5 | 1／5／5／5 |
| B本卷被跳过的中间题 | 到达0、回答0 | M11为0、0 |

预期输出：B本卷中间题到达、回答均为0；新路径即使无授权也包含两卷，参与问卷2、答卷／到达／回答各10、“笔记本”10；每份答卷最多计一次。旧路径仍按原授权口径，仅包含A卷。

实际输出：M11显示被跳过题为0／0；自动API测试中，新路径返回`scope=all_surveys`及2／10／10／10、选项10，旧路径返回1卷5份。

结果：通过。代码：[test_library_statistics.py](../backend/tests/test_library_statistics.py)中的`test_all_surveys_include_shared_users_without_consent_and_preserve_legacy_scope`；原单卷统计见第一阶段T06。

## 三、第二阶段新增业务测试

目的与前提：A已创建逻辑题目“U6设备类型”及版本1。

测试步骤：

输入：版本2新题干；恢复目标版本1。

预期输出：产生版本1→版本2和版本1→版本3两条来源关系；旧版不被覆盖；同键重试不重复创建。

### P2-11 自动纳入范围、版本隔离和小样本

### P2-12 数字平均值按答卷等权
